# 记录中心 · GitHub Pages 部署包

一套纯前端单文件应用，数据全部保存在本机浏览器（localStorage），不上传任何服务器。
GitHub Pages 只负责分发文件，看不到也拿不到你的数据。

---

## 一、这次更新了什么

### 1. 医院流向 → 升级为「进销存管理」
新增两个页签：**进销存**、**流水**。

- **进销存**
  - 顶部切换「进货（入库）」/「销量（出库）」，填医院、产品、数量、日期、备注即可
  - 保存后**实时自动计算**每家医院每个产品的剩余库存：库存 = 累计进货 − 累计销量
  - 汇总卡：涉及医院数、产品品种数、累计进货、累计销量、当前总库存、低于警戒项数
  - 每个产品右侧可填**警戒值**，库存低于该数字自动标红提醒补货
  - 销量导致库存为负时，会提示记得补录进货
  - 医院名会自动联想（复用了流向记录、客户产出里已有的医院）
  - 产品名直接输入即可，新的品名会自动加入备选项
  - 支持导出 Excel（含「当前库存」「进销流水」两张表）

- **流水**
  - 全部进货/销量记录，可按「只看进货 / 只看销量 / 本月 / 本周」筛选
  - 可删除单条，删除后库存立即重算
  - 支持导出 Excel

- 首页卡片会显示当前总库存，有偏低项时红字提示

### 2. 资源投入模块优化
- 新增「汇总」页：按医院 / 按客户 / 按类型统计投入次数，点任一条可下钻到明细
- 类型记忆：常用的投入类型自动排前面
- 本周 / 本月一键筛选
- 「复制上一条」快速回填
- 跨模块联动：客户产出 → 设置页里，每家医院/客户后面显示「投入 N」徽标

## 二、上传部署步骤（3 分钟）

1. 在 GitHub 新建一个仓库，例如 `record-center`，**设为 Public**（私有仓库要收费才能开 Pages）
2. 把本文件夹里的**全部内容**上传到仓库根目录：
   - `index.html`
   - `sw.js`
   - `manifest.webmanifest`
   - `icons/`（整个文件夹）
   - `.nojekyll`
   - `README.md`（可选）
3. 打开仓库 → **Settings** → **Pages**
4. Source 选 **Deploy from a branch**；Branch 选 `main`、目录选 `/ (root)` → **Save**
5. 等 1～2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可

> 上传方式任选：
> - 网页：仓库首页 → **Add file** → **Upload files**（直接拖整个文件夹进去）
> - 或装了 Git 的话：`git add . && git commit -m "deploy" && git push`

## 三、手机装到主屏（像 App 一样用）

- **iPhone**：Safari 打开网址 → 底部「分享」→「添加到主屏幕」
- **安卓**：Chrome 打开网址 → 右上角菜单 →「安装应用 / 添加到主屏幕」

装好后离线也能用（Service Worker 已缓存）。

## 四、以后怎么更新

只改 `index.html` 重新上传即可。覆盖后访问页面，会自动提示「发现新版本，点此刷新」。

> 如果提示没出来：强制刷新一次（手机长按刷新 / Ctrl+F5）。

## 五、重要提醒

1. **数据存在浏览器本地**，换设备、换域名、清浏览器缓存都会导致数据看不到。
   - 老数据迁移：在旧地址用各模块的「备份 / 导出」存成 JSON 或 Excel，再到新地址「导入」。
2. **不要用无痕模式**长期使用，关闭后数据会被清掉。
3. 建议每隔一段时间用「备份数据（JSON）」导一份存到微信文件传输助手或网盘。
4. 本包已包含离线缓存（`sw.js`），首次打开需要联网，之后断网也能用。
